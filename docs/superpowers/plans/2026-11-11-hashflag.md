# Hashflag Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a browser-based, tick-based ASCII capture the flag game for up to 200 players in one global room, with lightweight auto-named factions.

**Architecture:** A Go server owns all state. A pure game core (`internal/game`) resolves one tick from a map of player intents; a thin server layer (`internal/server`) runs the 1 s tick loop, WebSocket connections, lobby and rounds. A Vite + React + TypeScript client renders snapshots as monospace text and only sends intents.

**Tech Stack:** Go (module `hashflag`, go directive matching the installed 1.27 toolchain), `github.com/coder/websocket`, standard `testing`; Vite, React, TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-11-hashflag-design.md` (config schema: `docs/superpowers/specs/hashflag-config.schema.json`)

## Global Constraints

- Tick: `tickMs` 1000 (bounds 250 to 5000). Round: `roundTicks` 300. `maxPerTeam` 100.
- Ammo max 10, refill 1 per tick, only in own base. Projectile 2 cells/tick, range 14, cooldown 2 ticks, no pierce, no friendly fire.
- Tag: out 10 ticks, respawn at own base, tagged flag carrier drops flag where they stood. Safe line width 2, players on it cannot be tagged.
- Flag: dropped flag returns home after 30 ticks; carrier cannot throw.
- Walls: permanent (`decayTicks` null), `hitsToBreak` 1, `perPlayer` 1, `teamCap` 20, server rejects placement that seals the flag.
- Role skew cap 60% per team. Names not unique; per-tab session token; reconnect returns to slot.
- Factions: server-generated goofy names only, no free text; empty factions dissolve but keep all-time board entries; founder may reroll only while faction has 1 member.
- No database. All-time board is a JSON file; round stats are JSON lines. No accounts. Config files are operator-chosen on the server, never uploaded by players.
- Schema fields not implemented in v1 are rejected with a clear error. The client only sends intents; the server is authoritative.

## Review Focus

- Two or more players moving into one cell in the same tick: nobody moves, no overlap (Task 3).
- Flag carrier disconnects or leaves mid-round: flag drops at their position (Tasks 4, 8).
- Wall placements that are each fine alone but together seal the flag in the same tick: validated one at a time in a fixed order (Task 5).
- Client floods intents or sends garbage/oversized frames: one intent per tick (latest wins), bad frames dropped, connection survives (Task 8).
- Leaderboard file missing or corrupt at startup: server starts with an empty board and keeps a `.bad` copy of a corrupt file (Task 7).

### Task 3: World, movement, throwing, tagging

**Files:** Modify `internal/game/types.go`; Create `internal/game/step.go`; Test `internal/game/step_test.go`

**Interfaces:**
- Consumes: `GenerateMap`, `config.Config`.
- Produces: `type IntentKind int` (`Stay`, `Move`, `Throw`, `PlaceWall`); `type Intent struct{Kind IntentKind; Dir Dir}`; `type PlayerID string`; `type Player struct{ID PlayerID; Name string; FactionID string; Team Team; Role Role; Pos Pos; Ammo, CooldownLeft, OutLeft int; HasFlag bool; WallsPlaced int}`; `type Projectile struct{Pos Pos; Dir Dir; Owner PlayerID; Team Team; Traveled int}`; `type Event struct{Tick int; Kind EventKind; Player, Other PlayerID; Team Team; Pos Pos}` with kinds `Tagged`, `FlagPickedUp`, `FlagDropped`, `FlagReturned`, `Captured`, `WallPlaced`, `WallBroken`; `type World struct` (map, players, projectiles, walls, flags, `Tick int`, scores `[2]int`); `func NewWorld(cfg *config.Config, seed int64) (*World, error)`; `func (w *World) AddPlayer(p Player) *Player` (places at spawn: defenders near own flag, attackers at base edge; Ammo set to max); `func (w *World) RemovePlayer(id PlayerID)`; `func (w *World) Step(intents map[PlayerID]Intent) []Event`.

Step order (fixed, document in a comment): 1. decrement timers (cooldowns, out-time; respawn at 0). 2. Resolve moves: each mover advances up to `cellsPerTick` cell by cell, stopping at the first obstacle, wall, edge, or a cell occupied by a player who is not moving away; if two players target the same cell, neither enters it; swaps are blocked. 3. Launch throws (needs ammo and cooldown 0; carrier cannot throw; sets cooldown, spends ammo; projectile spawns at thrower's cell). 4. Advance every projectile cell by cell: stop and vanish at obstacle, edge or range; vanish and break a wall; hit the first enemy player not on the safe line and not out. 5. Apply tags. 6. Placements (Task 5), flag logic (Task 4). 7. Ammo refill for players in own base. 8. `Tick++`.

- [ ] **Step 1:** Tests: `TestMoveOneCell`, `TestTwoPlayersSameTargetNeitherMoves`, `TestSwapBlocked`, `TestMoveStopsAtObstacle`, `TestThrowHitsFirstEnemy`, `TestThrowDodgedByMovingOutOfPath` (mover leaves the line in the same tick, projectile passes), `TestProjectileIgnoresSafeLine`, `TestCooldownAndAmmo` (11th throw refused after ammo 0; cooldown blocks throw on following tick), `TestTagSendsOutAndRespawns` (out 10 ticks, then at own base with full ammo), `TestOutPlayerIntentsIgnored`, `TestAmmoRefillsOnlyInOwnBase`, `TestIdlePlayersCost` (200 idle players, `Step` under 5 ms).

### Task 4: Flag, capture, rounds

**Files:** Create `internal/game/flag.go`; Modify `step.go`; Test `internal/game/flag_test.go`

**Interfaces:**

Rules: an attacker on an enemy flag cell (not out, not already carrying) picks it up. A carrier moves at `carrierCellsPerTick` and cannot throw. ### Task 8: Server, tick loop, protocol

**Files:** Create `internal/server/protocol.go`, `hub.go`, `room.go`, `cmd/hashflag/main.go`; Test `internal/server/server_test.go`

**Interfaces:**
- Produces JSON messages (field `t` is the type). Client to server: `hello{token?, name}`, `setRole{role}`, `createFaction`, `joinFaction{id}`, `leaveFaction`, `rerollFaction`, `intent{kind, dir}`. Server to client: `welcome{token, playerId}`, `lobby{factions, board, waiting}`, `round{map, you}` (static map sent once per round), `state{tick, players, projectiles, walls, flags, scores, events}`, `roundEnd{winner, scores}`. `func NewRoom(cfg *config.Config, board *factions.Board, log *stats.Logger) *Room`; `func (r *Room) Run(ctx context.Context)`; `func NewHub(r *Room) http.Handler` (WebSocket endpoint `/ws`).

Rules: one intent per player per tick, latest wins, cleared after each tick (a missed tick means Stay). Frames over 1 KiB and unparseable frames are dropped without closing; more than 20 frames/second drops the connection. Rounds run back to back; players join mid-round, placed at spawn; players who cannot get a side wait in the lobby. Disconnect keeps the slot for 30 s for token reconnects, then calls `RemovePlayer` (which drops a carried flag). Credit captures to the capturer's faction on the board; save the board and append stats at round end.
